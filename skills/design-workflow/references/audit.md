# Инвентарь + аудит: методика 

## 1. Инвентарь — таблица по ролям, не по экранам

Каждый контрол живого DOM разложить в 4 группы:

| Группа | Признак | Иллюстративный пример |
|---|---|---|
| **Данные** | set once, редактируется редко, «чем агент владеет» | профиль, предпочтения, контакты |
| **Правила** | тюнятся в процессе использования | лимит, тон, грейды, регионы, площадки, dry-run* |
| **Каналы/инфра** | меняется при сбоях и раз в кампанию | подключённые сервисы, уведомления, сессии |
| **Не настройки** | другой владелец/ритм: рабочие очереди, админ-механики | рабочая очередь, dry-run*, сброс служебного состояния |

\* Dry-run может относиться к администрированию в зависимости от продукта. Критерий: **настройка = то, что пользователь меняет сам и осознанно**.

Пометки в колонках: `тюнится` / `set once` / `дубль` (роль пересекается с другой главой) / `⚠ нет лейбла` / `админ`.

Обязательно выписать:
- **Дубли-обманки** — где пользователь не может предсказать, где что лежит (например, контакты дублируются в двух секциях с разными названиями).
- **Зависимости** — что из чего генерируется и что блокирует что (резюме → парсинг → профиль; пустой профиль → агент не включится; trial → тумблер заблокирован на бэкенде). Сверять с доступной проектной документацией и кодом (пример: «Перегенерировать» не ретраит упавший парсинг → ложный успех с пустым профилем).
- **Скрытые лейблы** — контролы без подписи (spinbutton «100», combobox «Нейтральный») — кандидаты №1 на фикс в самом продукте, до редизайна.

## 2. Структурные причины «всё в кучу»

Сформулировать 4–6 причин, каждая = формат: **утверждение + evidence из проверенного источника (DOM, скриншот или код)**. Проверенные категории:
1. Диспропорция глав/секций (одна = 70% контента, другая = 1 ссылка).
2. Смешение ритмов (set-once данные рядом с частыми правилами).
3. Дубли-обманки (H6: распознавание vs вспоминание).
4. Невидимые зависимости (guard'ы, генерация из источника).
5. Один длинный столбец (мёртвая зона справа, поля-простыни; оптимум строки 50–75 знаков).
6. Чужие механики среди настроек (очереди, админ-действия).

## 3. Аудит — скорборд + линзы

**Скорборд Нильсена** (ux-heuristics): 10 эвристик, оценка 0–4 (0 = системный провал, 4 = ок; n/a если неприменимо). В артефакте — таблица с точками 0–4 и маленьким evidence.

**Линзы** (ux-principles): Fitts (тап-зоны 44px мобайл), Hick, Goal-Gradient, Peak-End (статус сохранения!), Tesler («Заполнить из резюме» вместо ручного ввода), Gestalt (дубли заголовков), Doherty, Jakob/Miller свёрнуты в Nielsen — не дублировать скорборд, линзы добавляют только новое.

**Finding** = `severity + тег (H№/закон) + место + evidence + конкретный фикс`:
- CRITICAL: главный параметр без лейбла; массовые деструктивные действия без undo.
- HIGH: скрытые guard'ы; нет статуса сохранения; 15+ секций без поиска; пересекающиеся сущности «контекста»; акцентный шум.
- MEDIUM: самодельные контролы (−/+ у грейдов — это диапазон!), нечитаемые тогглы, мобайл-тапы, нет контекстной помощи.
- LOW: дубли заголовков, контраст secondary.

Объём: quick — максимум 5, full — максимум 12. Не дополнять findings ради количества. Фильтр по severity в артефакте — обязательно.

## 4. Анти-нейрослоп чеклист (приёмка аудита)

- [ ] Каждый finding привязан к наблюдаемому контролу в DOM, скриншоте или исходном коде; источник и ограничения покрытия указаны
- [ ] Guard'ы продукта учтены (что реально блокируется, лимиты, режимы)
- [ ] Фиксы воспроизводимы: «слайдер + словесное последствие», а не «улучшить UX»
- [ ] Реальный контент/цифры; вымышленное — помечено или удалено
- [ ] Отчёт можно отдать в реализацию как есть (после пустых/error-состояний в коде)

## 5. Известные ловушки

- **Mojibake-снапшоты**: `text.encode('cp866').decode('utf-8')` — снапшоты agent-browser через Out-File на Windows искажаются, структура читаема, лейблы — только после декода.
- **Refs устаревают** после каждого клика — снимать снапшот заново или искать по role+name.
- **Аккордеоны**: глава «открыта» в DOM может быть не видна — снапшот после клика + wait 1200.
- **Счётчики DOM ≠ весь контент**: раздел может содержать одну ссылку, хотя сабтайтл обещал «бот и email». Доверять DOM, не подписям.
- **Мои домыслы из прошлых сессий** — не переносить в новый инвентарь без подтверждения текущим DOM, скриншотом, кодом или владельцем (например, неподтверждённые частоты и автоматические фильтры).

При отсутствии live-доступа аудит supplied screenshots/source допустим, но не подтверждает скрытые состояния, фактические переходы и runtime-поведение. Указывай эти пробелы; не называй покрытие полным.
